## 5. General project classification

| Classification | Options / Selection |
| --- | --- |
| Project type | Research / Product-system / Service. Provisional selection: Product-system |
| Reason | Idea-driven / Demand-driven / Documented need. Provisional selection: Demand-driven |
| Maturity | Feasibility / Technology development / Product development. Provisional selection: Technology development |
| Execution | Design / Build / Test. Provisional selection: Design, Build, Test |
| Relationship | Independent / Related to larger project. Provisional selection: Independent |

The project designs, builds and tests software that assessors use, so it is classified as product-system work rather than research or a service. Knowledge produced along the way, such as the comparison of retrieval methods on the evaluation set, serves the design of that software.

The sponsor's statement of need asks for support in assessing submissions to its platform and lists four requirements. Existing products already cover parts of this according to their own documentation: five innovation-management products describe duplicate suggestion when an idea is submitted, and three describe scouting for companies, technologies or patents that match a described need. In the material read, scouting results are not attached to the assessment of an individual submission (Section 9). Because suitable solutions exist for part of the need, "demand-driven" is the accurate reason under the form's definitions. "Documented need" would require evidence that existing products cannot be used by the sponsor, which this proposal does not have.

The maturity selection follows from the deliverable. At completion the project delivers a laboratory prototype that runs in a controlled environment on exported or proxy data and has been evaluated there; it is not integrated with the live platform and is not in operational use. This matches the form's technology-development band. The administrative funding track does not determine this selection.

No parent project has been identified. The prototype is designed to connect to the sponsor's submission platform in a later stage through a defined adapter interface (Section 11), but in the current project it is independent of other projects.
