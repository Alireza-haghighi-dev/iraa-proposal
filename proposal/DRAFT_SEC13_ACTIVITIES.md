## 13. Activities and deliverables

The current project designs, builds and tests a laboratory prototype in a controlled environment. The seven activities below cover the design of the prototype and its data handling, the evaluation tooling, three build activities divided by requirement, integration with evaluation, and handover. The prototype is not deployed on the live platform, does not write to it, and does not retrain itself from assessor decisions [DEC-028].

| No. | Main activity | Activity deliverable(s) | Key tasks | Effort (person-hours) |
| --- | --- | --- | --- | --- |
| 1 | Prototype design specification and data-protection baseline | Prototype design specification; information security risk assessment of the prototype's data flows (draft); data-handling and retention procedure | Specify the import format and field map and a configurable assessment template; define the record states, roles and approval rules as a transition table that the workflow tests use; specify the retrieval, connector, record, report, decision-log and identity interfaces and the later platform interface (specified, not built); assess risks for each data flow and trust boundary; specify the reference evaluation environment | 210 |
| 2 | Evaluation protocol, test collections and evaluation harness | Frozen evaluation protocol and judging guide; versioned test collections per data track with licence records; evaluation harness with a reproduction note | Check licences of candidate substitute datasets on their original distributions; write and freeze the protocol, including the significance procedure and acceptance criteria, before any test pool is judged; build time-ordered development and test splits; construct a substitute set for solution-example retrieval if the owner approves it [ISS-038]; build the metric and significance scripts; reproduce a published lexical baseline run to check the harness | 290 |
| 3 | Ingestion and retrieval for similar submissions and solution examples | Import and normalization components with an import report; index layer and retrieval service with the candidate configurations; resource and response-time measurement note | Import and validate exported records and register each solution-example source with its source type and permission note; normalize text, compute near-duplicate fingerprints and split long texts into passages; build lexical and vector indexes; implement lexical, dense and hybrid ranking and optional re-ranking with an evidence passage per candidate; set display thresholds, including the "no example above threshold" signal, on development data; measure encoding and search times at the agreed corpus sizes | 380 |
| 4 | External prior-art retrieval with query approval | Connector framework with one patent-service connector, query construction and query approval; connector test report | Build the connector interface with caching, rate-limit handling and provenance for each result; connect the patent service selected by the owner [ISS-040]; generate a query from the submission and let the assessor edit and approve the exact text before it is sent; provide manual entry of assessor-run search results as a fallback; test that no query can bypass approval | 210 |
| 5 | Assessment record, review interface and approval controls | Assessment record service with access control, audit log, report export and decision-log export; review interface; approval-enforcement test suite | Implement the record and its versioning so that only an authenticated assessor can approve and any change to an approved record needs approval again; implement roles and project-managed accounts; build review screens that show the matching passage before any score for every listed item; export approved records and logged decisions; generate workflow tests for every combination of state, event and role | 400 |
| 6 | Prototype integration and evaluation | Integrated prototype release; pilot report and configuration selection record; judgment files, run files and test logs; evaluation report by data track | Integrate activities 3 to 5 into one release on the reference environment; run pilot judging, revise the judging guide once and fix the remaining thresholds before the test run; select the retrieval configuration on development data; judge the test pools with double judging of a sample, and judge deeper for a sample of queries where no relevant item was found; run the test split once; run the approval, disclosure, attribution and response-time tests; report each result with its data track and confidence interval | 374 |
| 7 | Technical documentation and handover | As-built design specification with deployment and operation instructions; updated information security risk assessment and deletion record; source code with a component licence inventory; handover acceptance record | Update the design specification to the built prototype and write deployment instructions that another person can follow; update the risk assessment and delete project data as the retention procedure specifies; list every third-party component and model with its licence; demonstrate the prototype and record acceptance | 140 |

Total effort (provisional): 2,004 person-hours. The figure assumes that no sponsor data is released and that retrieval is evaluated on substitute data judged by project judges [ISS-002, AS-09]. If sponsor data or assessor time becomes available, the additional work is planned as listed in the working file, and assessor hours are recorded separately from project effort unless the owner decides otherwise [ISS-047].
